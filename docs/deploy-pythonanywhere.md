# Deploy to PythonAnywhere

This guide deploys this Django portfolio to a PythonAnywhere web app. Replace
`USERNAME` in every command with your PythonAnywhere username. The project
entry point is `rahidulislam.wsgi:application`; its SQLite database and
uploaded images/videos are configurable through `DJANGO_DATABASE_PATH` and
`DJANGO_MEDIA_ROOT`.

PythonAnywhere's [Django guide](https://help.pythonanywhere.com/pages/DeployExistingDjangoProject/)
documents the Web tab and WSGI workflow. Use a persistent account filesystem;
do not put production secrets, the database, or uploads in the Git checkout.

## Create the app and virtualenv

In **Web > Add a new web app**, choose **Manual configuration** and select the
Python 3.13 if offered, using that same version for the virtualenv below.
The pinned [Django 6.1.1](https://pypi.org/project/Django/6.1.1/) requires
Python 3.12 or newer. Do not assume that every pin in `requirements.txt` installs on
every PythonAnywhere image. If installation fails, resolve the version/package
mismatch before continuing. See [Changing the system image](https://help.pythonanywhere.com/pages/ChangingSystemImage/).

In a Bash console:

```bash
cd ~
git clone https://github.com/rahidulislam/rahidulislam.git
cd ~/rahidulislam
mkvirtualenv --python=/usr/bin/python3.13 rahidulislam-venv
pip install -r requirements.txt
pip install python-dotenv
```

Change the interpreter path to the version selected for the Web app. Install
`python-dotenv` explicitly: the WSGI configuration below loads the shared
environment file, and Django does not automatically load `.env` files.
Set the Web tab's virtualenv to
`/home/USERNAME/.virtualenvs/rahidulislam-venv` (check `echo "$VIRTUAL_ENV"`
in the activated console if it differs).

## Store secrets and persistent data

```bash
mkdir -p /home/USERNAME/.config/rahidulislam
mkdir -p /home/USERNAME/var/rahidulislam/media
touch /home/USERNAME/.config/rahidulislam/production.env
chmod 600 /home/USERNAME/.config/rahidulislam/production.env
```

Generate a key inside the activated virtualenv:

```bash
python -c "import secrets; print(secrets.token_urlsafe(64))"
```

Put this in `~/.config/rahidulislam/production.env`; never commit or publish
the file. The generated URL-safe key works with both the shell and dotenv
loaders; keep values shell-safe and quote any values containing spaces:

```dotenv
DJANGO_SECRET_KEY=PASTE_THE_GENERATED_KEY_HERE
DJANGO_DEBUG=false
DJANGO_ALLOWED_HOSTS=USERNAME.pythonanywhere.com
DJANGO_CSRF_TRUSTED_ORIGINS=https://USERNAME.pythonanywhere.com
DJANGO_DATABASE_PATH=/home/USERNAME/var/rahidulislam/db.sqlite3
DJANGO_MEDIA_ROOT=/home/USERNAME/var/rahidulislam/media
```

Use the exact hostname shown on the Web tab; EU accounts may use
`USERNAME.eu.pythonanywhere.com` instead. Open the site using HTTPS: this
project redirects HTTP and enables secure cookies when debug is disabled.

For a custom domain, add it to `DJANGO_ALLOWED_HOSTS` and add its HTTPS origin
to `DJANGO_CSRF_TRUSTED_ORIGINS`, comma-separated.

## Migrate and collect static files

The console does not automatically read `production.env`. Export it before
each management command:

```bash
workon rahidulislam-venv
cd ~/rahidulislam
set -a
. /home/USERNAME/.config/rahidulislam/production.env
set +a
python manage.py check --deploy
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py createsuperuser  # run once, if needed
```

Review seeded content after migrations. If this is an existing site, copy its
database and media into the persistent paths and back them up before migrating.
The contact form stores submissions in the database; it does not send email.

## Configure WSGI

Open the WSGI file shown in the Web tab and replace it with the following,
changing `USERNAME` and the checkout path if necessary:

```python
import os
import sys
from dotenv import load_dotenv

project_home = '/home/USERNAME/rahidulislam'
if project_home not in sys.path:
    sys.path.insert(0, project_home)

load_dotenv('/home/USERNAME/.config/rahidulislam/production.env', override=False)
os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'rahidulislam.settings')

from django.core.wsgi import get_wsgi_application
application = get_wsgi_application()
```

This explicit load makes the WSGI process use the same external file exported
by the console. Set the virtualenv in the Web tab and click **Reload**. Check
the WSGI error log if startup fails.

## Map static files and media

In the Web tab's **Static files** section add the following
[static and media mappings](https://help.pythonanywhere.com/pages/DjangoStaticFiles/):

| URL | Directory |
| --- | --- |
| `/static/` | `/home/USERNAME/rahidulislam/staticfiles` |
| `/media/` | `/home/USERNAME/var/rahidulislam/media` |

Reload after changing mappings. The first directory is generated by
`collectstatic`; the second is persistent admin-uploaded media. Production
URL configuration does not use Django's development media serving.

## Verify and operate

The CV is generated in memory with ReportLab; no PDF upload or export is
needed. Verify a contact submission appears in the admin.

Check the homepage, `/projects/`, `/cv/download/`, `/admin/`, contact form,
CSS/JavaScript, and an uploaded image/video. Host or CSRF errors usually mean
the two host variables were not exported or the web app was not reloaded.

For updates, back up first, pull the intended commit, install changed
requirements, export `production.env`, run `migrate` and `collectstatic
--noinput`, then reload:

```bash
workon rahidulislam-venv
python - <<'PYBACKUP'
import sqlite3
from datetime import datetime
from pathlib import Path
root = Path('/home/USERNAME/var/rahidulislam')
stamp = datetime.now().strftime('%Y%m%d-%H%M%S')
with sqlite3.connect(f"file:{root / 'db.sqlite3'}?mode=ro", uri=True) as source:
    with sqlite3.connect(root / f'db-{stamp}.sqlite3') as backup:
        source.backup(backup)
PYBACKUP
tar -czf /home/USERNAME/var/rahidulislam-media-$(date +%F).tar.gz -C /home/USERNAME/var/rahidulislam media
```

Pause content edits and uploads while backing up to keep database and media
consistent. Keep a copy of backups off the account. After backup:

```bash
cd ~/rahidulislam
git pull --ff-only
pip install -r requirements.txt
set -a
. /home/USERNAME/.config/rahidulislam/production.env
set +a
python manage.py check --deploy
python manage.py migrate
python manage.py collectstatic --noinput
```

Stop if a command fails; reload from the Web tab only after the commands pass.
Review deployment-check warnings before launch. If a release fails, restore
its matching code, dependencies, database backup, and media together rather
than assuming a code rollback reverses migrations.

Use the Web tab error log for import/startup errors and the server log for
request errors. Common causes are an incorrect virtualenv or WSGI path,
missing packages, unexported variables, and static/media mappings pointing at
the wrong directories. Back up SQLite and media together because database
records reference uploaded files.
